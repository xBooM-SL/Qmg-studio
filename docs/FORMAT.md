# QMG (Qmage) animation format - version 15, RGB565

Reverse engineered; every statement below was checked by re-implementing the decoder and comparing
the output bit-for-bit with Samsung's `libQmageDecoder.so`.

A `.qmg` animation is a plain concatenation of frames. Each frame starts with a 0x20 byte header.

| offset | meaning |
|---|---|
| 0x00 | `QM` |
| 0x02 | version (0x0f) |
| 0x03 | pixel format (0 = 16-bit RGB565) |
| 0x04 | flags (0x80 = animation) |
| 0x06 / 0x08 | width / height (u16) |
| 0x0b | 0x20 |
| 0x0c | u32 frame size. Keyframe: size / 4. Other frames: size in bytes |
| 0x10 | u16 total frame count |
| 0x12 | u16 frame number (1-based). Frame 1 is the keyframe, others are delta frames |
| 0x14 | u16 unknown (0 in bootsamsung.qmg, 33 in shutdown.qmg) |
| 0x18 | u32 keyframe: offset of stream B. Delta frame: offset of the raw-pixel stream |
| 0x1c | u32 keyframe: offset of stream C. Delta frame: 0 |

Stream A always starts at 0x20 and is a bitstream (MSB first).

## Delta table
`Qmage_ori_deltaRGB_new` in libQmageDecoder.so: int32 entries starting 8 bytes after the symbol.
Entries 2..255 are used. A pixel = (predictor + table[i]) mod 65536.
An index i is coded as `n` (3 bits) and `v` (n+1 bits): i = (2 << n) + v, n = 0..6. `n = 7` means a raw pixel.

## Keyframe (frame 1)
Image is split into 4x4 blocks, raster order. For each block, read a 2-bit mode from A:
* 3: every row of the block is filled with the pixel to the left of the block
* 0 / 1 / 2: predictor is the left / upper / upper-left neighbour pixel (per pixel, already decoded)

For modes 0-2: read a 16-bit mask word from C (little endian). For pixel k = 0..15 (row-major):
* mask bit = 1: pixel = predictor
* else read `n` (3 bits) from B. If n = 7: pixel = next 16-bit word from C. Otherwise read n+1 bits `v` from A,
  pixel = predictor + table[(2 << n) + v].

## Delta frames (frame 2...)
Start from the previous frame. Image is split into 16x16 macroblocks, raster order. Everything is in stream A, except raw pixels.
Width and height must be multiples of 4. When a size is not a multiple of 16, the macroblocks on the right edge and the bottom
edge are smaller (they contain fewer 4x4 sub-blocks) but use the same syntax, with one difference: **a partial macroblock is
skipped with a single `1` bit** instead of `11`.
* bits `11` (partial macroblock: bit `1`): macroblock unchanged
* bit `0`: 16 sub-blocks of 4x4 (row-major); each has a 2-bit mode as above (3 = replicate left),
  and for modes 0-2 each pixel is: bit 1 = predictor; bit 0 followed by `n` (3 bits): n = 7 -> next 16-bit
  word of the raw stream (located at header[0x18]), else n+1 bits `v` and the table delta.
* bits `100` / `101`: other macroblock types (block copy with motion vector, ...) - decoded by Samsung's
  decoder, not generated by this encoder.
